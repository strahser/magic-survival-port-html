````markdown
# ЗАДАНИЕ: автономная балансировка + регресс-тест «Magic Survival (ASCII)»

## Роль
Ты — автономный баланс-тестировщик и QA. Ты НЕ играешь руками: ты гоняешь
headless-симулятор, читаешь метрики, вносишь правки в разрешённые файлы и
добиваешься критериев приёмки. Действуй циклами, фиксируй каждую правку.

## Контекст / файлы
- Игра: `index.html` + `*.js` (браузер, canvas, ASCII).
- Баланс: `balance.js` (все кривые/экономика), `spells.js` (урон/КД/уровни заклинаний).
- Данные (НЕ трогать): `data.js`, `classes.js`, `artifacts.js`, `combos-data.js`, `theme.js`.
- Логика/рендер (НЕ трогать): `game.js`, `render.js`, `combos.js`, `test.js`.
- Симулятор: `sim/sim-model.js`, `sim/sim-grade.js`, `sim/sim-tune.js`, `sim/sim-report.js`.
- Запуск теста: `node sim/node_runner.js` → stdout-отчёт + `balance-report.json`.

## Шаг 0. Smoke-тест (обязателен перед всем)
1. Выполни `node sim/node_runner.js`.
2. Если падает с ReferenceError/SyntaxError — это БАГ загрузки: сообщи файл/строку
   и остановись (правки в `sim/*` и дата-файлы для устранения синтаксиса ДОПУСТИМЫ,
   но не меняй игровую логику).
3. Если отчёт собрался — переходи к балансировке.

## Метрики и шкала
- `gradeScore` 0–100 → буква: 90+ S, 75–89 A, 60–74 B, 40–59 C, <40 D.
- `clearRatio` (DPS/приходящее HP) по минутам; коридоры:
  1–2 мин [1.2, 2.6]; 3–5 мин [1.05, 2.0]; 6–10 мин [0.95, 1.6].
- Отчёт даёт: по классу НОРМА/ХАОС (балл), выживаемость p10/p50/p90,
  времена боссов, теплокарту (▼ опасно / · норма / ▲ легко), автоподбор.

## ЦЕЛИ (что считать хорошим балансом)
1. Ранг: игрок чувствует силу в начале, давление в миде, лейт требует комбо,
   но не является «стенкой».
2. Нет мёртвых и доминирующих классов.
3. Боссы убиваются за 4–25 с (не мгновенно и не тайм-аут).
4. Риск/награда: ХАОС и обеты заметно сложнее, но проходимы.

## КРИТЕРИИ ЗАВЕРШЕНИЯ (acceptance) — всё должно быть true
- [ ] `overall.norma >= 75` И `overall.chaos >= 60`.
- [ ] Для каждого класса `classes[cls].norma >= 60`.
- [ ] Для каждого класса `classes[cls].survP50 >= 300` (≥5 мин на норме).
- [ ] Все времена боссов в [4, 25] с.
- [ ] Теплокарта: нет `▼` на минутах 1–2; не более одной `▼` на минутах 8–10.
- [ ] Разброс классов: max(norma) − min(norma) <= 20.

## ЧТО РАЗРЕШЕНО менять (и пределы)
- `balance.js`: любые поля, НО:
  - `hpGrowth/hpCurve/dmgGrowthT` в пределах ±30% от исходных;
  - `armorCap` в [8, 16]; `bosses.*` и `economy.*` — только если на это прямо
    указывает рекомендация отчёта.
- `spells.js`: базовый урон/`n`/`aoe`/`cd` любых заклинаний в пределах ±15%
  за одну итерацию; НЕ менять структуру `lv` и поля `combo`.
- `sim/*` — только фиксы синтаксиса/загрузки (см. Шаг 0).

## ЧТО ЗАПРЕЩЕНО
- Менять `game.js`, `render.js`, `combos.js`, `test.js`, дата-файлы, `index.html`.
- Менять механики (формулы, ИИ врагов, события) — только числа в разрешённых файлах.
- Применять правку, которая даёт деградацию любого класса > 3 баллов.

## Цикл работы (максимум 6 итераций)
1. `node sim/node_runner.js`; сохрани текущий `balance-report.json` как baseline.
2. Проверь критерии. Если все true — ГОТОВО, переходи к отчёту.
3. Иначе возьми блоки «Рекомендации» и «Автоподбор» и примени ОДНУ-ДВЕ правки
   в `balance.js`/`spells.js` (в разрешённых пределах).
4. Перезапусти сим. Прими правку, если `overall.norma` вырос ≥ +1 И нет класса
   с деградацией > 3. Иначе откати правку.
5. Повтори с шага 2. Остановись при выполнении критериев или после 6 итераций.

## Регресс
После каждой принятой правки убедись, что `overall.chaos` не упал ниже baseline
более чем на 3 и что ни один класс не провалил `survP50 < 300`.

## Стоп-условия (немедленно остановиться и сообщить)
-Smoke-тест падает после фиксов синтаксиса.
- Критерии недостижимы в пределах разрешённых правок — опиши, какие ограничения
  мешают и какие поля/пределы нужно расширить (не расширяй сам).
- Обнаружено расхождение модели и игры, влияющее на выводы.

## Формат финального отчёта
1. `ИТОГ: НОРМА xx [L] / ХАОС yy [L]` (и по классам одной строкой).
2. Список применённых правок: `файл: поле было → стало` (+ дельта баллов).
3. Отклонённые правки и причина.
4. Какие критерии выполнены / какие открыты и почему.
5. Приложи финальный `balance-report.json`.
````

````markdown
# START.md — baseline + приоритетные правки (старт балансировки)

## 1) Baseline (ожидание модели — ПОДТВЕРДИ прогоном)
Запусти `node sim/node_runner.js` и сверь с оценкой. Если реальные цифры
сильно расходятся с ожиданием (>10 балл.) — сначала проверь, что сим читает
те же `balance.js/spells.js`, что игра.

| Метрика | Ожидание (аналитически) | Факт (заполни) |
|---|---|---|
| overall.norma | ~70–80 [B/A] | |
| overall.chaos | ~55–70 [C/B] | |
| Ранний clearRatio (1–2м) | 1.8–2.4 (верх коридора) | |
| Средний (3–5м) | 0.9–1.2 (возможна ▼ на 3–4м) | |
| Лейт (6–10м) | 0.9–1.4 (зависит от эво) | |
| survP50 (норма) | 300–540 | |
| Боссы | 6–20 с | |

Ожидаемый профиль: старт комфортный, **провал в миде (3–5м)** до первых
эволюций, лейт держится только на комбо. Это и есть главная мишень.

## 2) Приоритетные «подозреваемые» (порядок = приоритет)
Каждая строка: поле (текущее) → что двигает → первое предложение.

1. `enemies.hpCurve` (0.055) — лейт-HP. Если минуты 6–10 ▼ и survP50<400:
   → попробуй **0.048**. (в пределах ±30%)
2. `enemies.hpGrowth` (0.026) — мид-HP. Если ▼ на 3–5м: → **0.022**.
3. `enemies.dmgGrowthT` (430) — входящий урон лейта. Если clearRatio в норме,
   но survP50<300 (давит урон, не толпа): → **470**. Если слишком легко: → **400**.
4. `player.healOnLevel` (10) — сглаживает смертность. Если p10 ≪ p50
   (смерти от случайных пиков): → **12**.
5. `enemies.elite.hpMul` (4.0) — шипы элита/стражей. Если p10-провалы при
   нормальном p50: → **3.5**.
6. Базовый урон отстающего класса в `spells.js` — если разброс классов >20:
   точечно **+10%** к `dmg` стартового/ядерного заклинания слабого класса.

## 3) Первые два эксперимента (сделай в любом случае)
- E1: `hpCurve 0.055→0.048`. Ожидай: лейт-ratio +0.1…0.2, survP50 +40…80,
  overall.norma +2…5. Прими, если нет класса с деградацией >3.
- E2 (если после E1 мид всё ещё ▼): `hpGrowth 0.026→0.022`. Ожидай: 3–5м +0.1.

После каждого: регресс — `overall.chaos` не ниже baseline−3, ни один класс
не провалил `survP50<300`.

## 4) Когда НЕ трогать числа
Если теплокарта ровная (·) и все критерии true — не «улучшай» баланс,
завершай с выводом «баланс в допуске».
````
