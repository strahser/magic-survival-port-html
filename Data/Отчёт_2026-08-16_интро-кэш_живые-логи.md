## 1. Инцидент

**Симптом (репорт пользователя):** после интро «[ любая клавиша — начать ]» нажатие клавиши ничего
не делает — экран интро остаётся.

**Консоль браузера пользователя (Chrome):**
```
render.js:17 Uncaught ReferenceError: VOWS is not defined
    at buildMenu (render.js:17:97)
    at render.js:21:21
```

Строка `render.js:17` — `$('dailyLabel').textContent='сегодня: '+CLASSES[dc.cls].name+' · '+
(dc.vow?VOWS[dc.vow]:'без обета')+' · '+(dc.diff===2?'ХАОС':'норма')+' · '+dc.mut.name;`

`buildMenu()` вызывается при загрузке (render.js:21) ДО регистрации `keydown`-обработчика
(render.js:133). Падение на `VOWS` → обработчик клавиш не регистрируется → интро не закрывается.

## 2. Диагностика (доказательства)

| Проверка | Результат |
|---|---|
| `classes.js` на диске (строка 8) | `const VOWS={fury:..., greed:..., swift:..., stone:...}` — есть |
| `git show HEAD:classes.js` | та же строка 8, VOWS на месте |
| Живой сервер `localhost:8000` (curl) | `classes.js` отдаётся С VOWS (строка 8), `render.js` корректный |
| Headless Chrome, file:// (3 прогона) | `state0:"menu" → s1:"intro" → s2:"play"`, errors: [] |
| Headless Chrome, http://127.0.0.1:8123 | то же, зелёно |
| Headless Chrome, http://localhost:8000 (живой сервер) | то же, зелёно |

**Вывод:** код и сервер исправны; браузер пользователя отдавал **закэшированную старую версию**
`classes.js` (в ней `VOWS` отсутствует). `python http.server` не шлёт `Cache-Control`, Chrome
кэширует по эвристике → старая вкладка/кэш показывал смесь старого `classes.js` + нового
`render.js`. Решение для пользователя: Ctrl+Shift+R / инкогнито-окно. Код НЕ менялся.

**Замечание для дальнейшего:** `start.bat` использует `python -m http.server 8000` (без
`/api/log`), а `serve.py` (есть в репо) умеет принимать логи забегов → пользователю стоит
перейти на `serve.py` (см. п.4).
